# Database schema histories and the v36 merge

Enhanced and upstream forked after the shared v25 schema. Enhanced c87d37f2 shipped
v35; upstream 64452581 shipped v33. Their v26..33 numbers describe different schemas.
Enhanced also shipped a different, now-retired v29 at 87195679. Never use a version
number alone to decide which branch's migration to run.

## Exports

- The canonical database directory keeps common v1..25 and upstream v26..33.
- Canonical v34..35 are the previously shipped Enhanced exports; they are historical
  records, not an auto-migration sequence following upstream v33.
- The enhanced/ directory preserves Enhanced v26..35 byte-for-byte from c87d37f2.
- The enhanced-legacy29/ directory preserves the actual retired v29 from 87195679.
- Canonical v36 is generated by Room/KSP from the combined entities. Do not edit its
  identity hash manually or overwrite any historical export to resolve a collision.

## Upgrade paths

[MigrationTo36](../src/main/java/me/rerere/rikkahub/data/db/migrations/MigrationTo36.kt)
registers direct 25..35 → 36 bridges. Earlier versions use the unchanged shared
migrations through v25, then the bridge. No auto migrations cross the fork.

The bridge checks actual table/column presence, adds the missing structures from
both branches, imports old memories into profile files, seeds consolidation markers,
backfills usage only when the ledger is absent, and upgrades the message index.
Existing profiles, consolidation markers, usage rows and Enhanced jobs, agents,
workflow runs/results/agent rows are preserved. The original MemoryEntity and
retired workspace_workflows/workspace_workflow_runs tables remain intact. There is
no destructive fallback. Room validates the merged schema before opening it.

## Regression tests

[MigrationTo36Test](../src/androidTest/java/me/rerere/rikkahub/data/db/migrations/MigrationTo36Test.kt)
loads 20 exact historical exports: shared v25, upstream v26..33, Enhanced v26..35,
and retired v29. It inserts one sentinel row in every original table, validates
against Room's v36 export, compares every original column, checks memory/usage
conversion and replay safety, and exercises the production factory's migration
registration for both branch heads, shared v25 and retired v29. Extra legacy tables
are intentionally permitted by validation and explicitly checked for preservation.
The Android tests require an emulator or device.

The [standalone verifier](../src/test/python/verify_merge_migration.py) runs the real
production Kotlin migration code through a minimal JVM adapter backed by SQLite
JDBC. It checks the same 20 histories and compares columns, defaults, keys, indexes
and foreign keys against the KSP-generated v36 schema; it does not replace Android
Room/factory tests. Run from the repository root:


```sh
python3 app/src/test/python/verify_merge_migration.py
```

Requirements: Python 3.10+, kotlinc, Java, and sqlite-jdbc. The runner uses an existing
Gradle-cached JDBC jar, or accepts --sqlite-jdbc /path/to/sqlite-jdbc.jar. It builds
only its isolated migration harness in a temporary directory; it never runs Gradle
or modifies the exports.
